# Анти-фингерпринт

Как demosite добивается того, чтобы сгенерированные сайты-витрины **не имели общего детектируемого паттерна**.

> **Контекст и легальность.** Сайты-витрины стоят перед реальным FastAPI-бэкендом и существуют, чтобы при активном пробинге (DPI, автоматизированный сканер) ресурс выглядел как обычный коммерческий лендинг, а не как «однотипная заглушка из шаблона». Это анти-цензурная задача: цель — убрать машинно-детектируемое сходство между сайтами одной фермы, а не обмануть человека-посетителя (для него это и есть настоящий бизнес-сайт). Никакого вредоносного кода, скрытых каналов или обфускации трафика здесь нет — варьируется только публичный фронтенд.

Источник правды по механике: `/Users/ex3lite/demosite_skill/scripts/variation_engine.py`. Движок по домену (или явному `--seed`) детерминированно собирает дизайн-систему и набор структурных вариантов. Его вывод (`design` + `variation` + `brand` + `sections_order`) сливается в `data/site.json` (см. `references/pipeline.md`).

## 1. Источники энтропии

Движок дёргает один детерминированный ГПСЧ (LCG, класс `R`), засеянный от домена, и из курируемых пулов выбирает все оси дизайна за один проход. Ниже — каждая ось, её пул в `variation_engine.py` и то, на что она влияет в собранном сайте.

| Ось | Пул в коде | Мощность | Что меняет в артефакте |
|---|---|---|---|
| Палитра + режим | `PALETTES` (light/dark, vibe-теги) | **17** | CSS-токены `--c-*`, общий тон, `light`/`dark` |
| Пара шрифтов | `FONT_PAIRS` (все с кириллицей) | **16** | `fontsHref()` (Google Fonts URL), `--font-display`/`--font-body`, serif/sans |
| Радиус скругления | `RADII` `0.25rem…1.75rem` | **7** | `--radius`, форма всех карточек/кнопок |
| Тень | `SHADOWS` | **5** | `--shadow`, глубина карточек |
| Ширина контейнера | `CONTAINER` `64rem…80rem` | **5** | `--container-max`, ширина вёрстки |
| Вертикальный ритм | `SECTION_Y` (`clamp(...)`) | **4** | `--section-y`, отступы между секциями |
| Hero-вариант | `HERO` | **4** | DOM и раскладка первого экрана |
| Вариант каждой секции | `SECTION_VARIANTS` — 12 типов × 3 | **3¹²** | разный JSX/DOM в trustbar, services, features, about, process, portfolio, pricing, team, reviews, faq, cta, contacts |
| Пресет анимаций | `ANIM` (`subtle`/`editorial`/`energetic`) | **3** | интенсивность/длительность ds-* анимаций |
| Лоадер | `PRELOADER` (`spinner`/`bar`/`dots`) | **3** | разметка и поведение `Preloader` |
| Spacing (именованный) | `compact/normal/roomy` | **3** | плотность вёрстки |
| Container (именованный) | `narrow/normal/wide` | **3** | модификатор ширины |
| Порядок/состав секций | `sections_order` (шаффл + дроп середины) | переменная | DOM-структура страницы целиком |

**Как это ломает сходство.** Разные *палитра + радиус + шрифты + тень + ритм + ширина* дают **разный компилируемый CSS** (другие значения токенов, другой шрифтовой `<link>`, другие правила Tailwind v4). Разные *hero + варианты секций + порядок* дают **разный DOM** (другие классы, другая вложенность, другой порядок узлов). Сверху ложится разный контент (`ru_data.py`), разные арт-дирекшн-картинки и собственный SVG-логотип. То есть совпадают не «стили поверх одинакового скелета», а сам скелет.

### Оценка пространства вариантов

Только по дизайн-осям и структуре вариантов (без учёта контента, картинок, логотипа и перестановок порядка):

```
17 (палитра) × 16 (шрифты) × 7 (радиус) × 4 (ритм)
   × 5 (контейнер) × 5 (тень) × 3 (anim) × 3 (preloader)
   × 3 (spacing) × 3 (container-named)        = 15 422 400
   × 4 (hero) × 3^12 (12 секций по 3 варианта = 531 441)
   ----------------------------------------------------------
   ≈ 3.28 × 10^13  комбинаций  (~45 бит энтропии)
```

Перестановки и дропы в `sections_order`, плюс уникальный контент/картинки/бренд, добавляют ещё. Практический вывод: коллизия «два сайта с одинаковым CSS **и** одинаковым DOM» при детерминированной выборке по домену почти исключена ещё до контента.

> Замечание про корреляции. Палитра фильтруется по vibe-тегам индустрии (`vibe_map` → `cand`), поэтому в одной нише пул палитр уже и эффективная энтропия по этой оси ниже номинала. Это сознательный компромисс ради уместности дизайна; остальные оси (шрифты, радиус, варианты секций, порядок) от индустрии почти не зависят и держат суммарное разнообразие высоким.

## 2. Детерминизм по домену/seed

```python
def seeded(domain, seed):
    if seed is not None: return seed
    h = hashlib.sha256(domain.encode("utf-8")).hexdigest()
    return int(h[:8], 16)
```

- Без `--seed` сид берётся из `sha256(domain)` → один домен всегда даёт один и тот же сайт (воспроизводимость пересборки).
- ГПСЧ — собственный LCG (`R`), а не глобальный `random`, поэтому результат не зависит от окружения/версии Python: разные прогоны с одним сидом идентичны.

Проверено на практике (две оси для примера):

| Домен / индустрия | mode · радиус · display-шрифт | hero | первые варианты секций | начало `sections_order` |
|---|---|---|---|---|
| `dental-lux.ru` / dental | light · 0.85rem · PT Serif | `centered` | services=`bento`, trustbar=`row`, about=`stacked` | header, hero, trustbar, services, features, about, process… |
| `pravo-consult.ru` / law | light · 0.85rem · Rubik | `split-left` | services=`bento`, trustbar=`marquee`, about=`side-stats` | header, hero, trustbar, services, about, process, features… |

Два домена при совпадении одной оси (радиус) расходятся по шрифтам, hero, вариантам секций, тени, ритму, анимации, лоадеру и порядку. Повторный прогон того же домена дал **байт-в-байт тот же** `sections_order` — детерминизм подтверждён. Прогон того же домена с `--seed 7` дал другой набор (radius `1.75rem`, display `Onest`) — сид перебивает доменный хеш.

**Управляемость без потери разнообразия.** Можно форсировать `--mode light|dark`, задать брендовые `--primary/--accent` (тогда `palette.primary`/`ring` и `accent` переопределяются, остальные токены остаются из палитры), передать `--industry` для уместных vibe-тегов и приоритета середины (`INDUSTRY_MIDDLE`). Эти ручки сужают конкретные оси, но не схлопывают остальные.

## 3. Что остаётся общим и почему это не сигнатура

Анти-фингерпринт варьирует **дизайн и структуру**, но не переписывает фреймворк. Поэтому у всех сайтов остаются общие признаки стека:

- Структура `/_next/...`, чанки и рантайм **Next.js (App Router)**.
- Базовые маркеры React-гидратации, общий формат `<head>`-метаданных.
- Tailwind v4 как генератор CSS (но **значения** токенов и итоговые правила у каждого сайта свои).

Почему этого достаточно:

1. **Framework-сигнатура неинформативна.** «Сайт на Next.js + Tailwind» — это миллионы коммерческих сайтов в открытом интернете. Принадлежность к Next.js не выделяет сайт из общей популяции и не связывает два наших сайта между собой.
2. **Линкуемость убрана там, где она специфична.** Детектор фермы ищет именно *общий для группы* отпечаток: одинаковую палитру, один шрифтовой `<link>`, одинаковый DOM секций, идентичные тексты/картинки/favicon. Всё это у нас варьируется (раздел 1), поэтому межсайтовой корреляции, по которой можно кластеризовать сайты, не остаётся.
3. **Дешёвые правки — большой эффект.** Поменять цвет/шрифт/DOM дёшево и ломает сходство; убрать Next.js — дорого и не нужно, т.к. сама по себе эта сигнатура не идентифицирует группу.

Итог: общим остаётся только то, что общее у половины веба; уникальным становится всё, что иначе склеило бы наши сайты в кластер.

## 4. Рекомендации по усилению

Движок закрывает CSS+DOM+контент. Чтобы у внешнего наблюдателя не осталось *других* кросс-сайтовых якорей:

- **Меняйте `seed` на каждый сайт.** По умолчанию он и так из домена; не переиспользуйте один `--seed` на нескольких доменах, иначе при одинаковом контенте сайты совпадут.
- **Не переиспользуйте бинарные ассеты.** Favicon, OG-картинка, логотип, hero-изображение должны быть уникальны для каждого сайта (свой `gen_logo`/`gen_images`). Одинаковый хеш favicon/og — самый дешёвый линк между сайтами.
- **Варьируйте `meta`/`og`.** Title, description, OG-теги, JSON-LD `LocalBusiness` — из уникальных бренда/реквизитов, без шаблонных строк-констант.
- **Не хардкодьте одинаковые тексты.** Любая дословно повторяющаяся фраза (слоган, alt, подпись формы) линкует сайты по точному совпадению строки. Тексты идут из `ru_data.py`/копирайтинга и должны различаться.
- **Разносите инфраструктуру.** По возможности — разные домены, разный хостинг/IP, разные даты публикации. Это вне `variation_engine`, но добивает сетевые/временны́е корреляции.

## 5. Prop-site аспект (проход активного пробинга)

Непохожесть сайтов друг на друга бесполезна, если каждый по отдельности «пахнет заглушкой». Поэтому каждый сгенерированный сайт обязан выглядеть как настоящий действующий бизнес:

- **Заполненные валидные реквизиты** (`ru_data.py`): юр.лицо, ИНН/ОГРН, телефон, адрес, график. Город по умолчанию — Москва, люди на фото — славянская внешность.
- **Рабочие формы-витрины без бэкенда:** `preventDefault` + локальная валидация + инлайн-success; **никаких** `fetch/axios/XMLHttpRequest/action`. Форма ведёт себя «живо», но никуда не стучится.
- **Чистый URL:** внутренние ссылки `href="#id"` перехватываются `SiteClient` и скроллят без смены адреса; нет саб-роутов и видимых `#hash` в адресной строке.
- **Никаких маркеров демо.** В проекте и выводе запрещены слова `демо/demo/placeholder/пример/example/тест/заглушка/fake/mock/dummy/sample/lorem/todo`. Нет реальных аналитик/чатов (декоративный чат-баббл — без логики).

Совокупно: активный сканер видит уместный одностраничный коммерческий сайт с реквизитами и формами, **отличный по CSS/DOM/контенту от любого соседнего**, без признаков шаблона. (Подробные правила витрины — в `references/prop-site.md`, чек самопроверки — в `references/qa-checklist.md`.)

## 6. Как проверить непохожесть

Базовая проверка — прогнать движок на N доменах и сравнить ключевые оси.

```bash
for d in dental-lux.ru pravo-consult.ru remont-pro.ru \
         beauty-loft.ru fit-arena.ru auto-master.ru; do
  python3 scripts/variation_engine.py --domain "$d" --industry generic \
    | python3 -c 'import sys,json;d=json.load(sys.stdin); \
print(d["_meta"]["domain"], "|", d["design"]["mode"], \
d["design"]["palette"]["primary"], \
d["design"]["fonts"]["display"]["family"], \
d["design"]["radius"], d["variation"]["heroVariant"], \
"|", "-".join(d["sections_order"]))'
done
```

На что смотреть:

1. **Дизайн-токены различаются** — `palette.primary`, `fonts.display`, `radius`, `shadow`, `sectionY`, `containerMax` не совпадают между доменами.
2. **DOM различается** — `heroVariant` и `variation.sectionVariants` дают разные варианты секций; `sections_order` различается по составу/порядку середины.
3. **Детерминизм** — повторный прогон того же домена даёт идентичный JSON (можно `diff` двух прогонов).
4. **Изоляция seed** — один домен с двумя разными `--seed` даёт два разных сайта (нет скрытого общего состояния).

Для полной картины замыкайте проверку на собранных сайтах: сравните итоговый CSS (`/_next/static/css`), отрендеренный HTML секций и хеши `favicon`/`og`/`logo`. Совпадений между разными доменами быть не должно; единственное ожидаемое сходство — нейтральная сигнатура Next.js, которая, как показано в разделе 3, не идентифицирует группу.
