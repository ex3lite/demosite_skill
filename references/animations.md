# references/animations.md

> Анимационный плейбук скилла **demosite** (автономный генератор премиальных РУ
> сайтов-витрин). Кодирует принципы Emil Kowalski под наш стек: Next.js App Router,
> Tailwind v4, серверные секции + один клиентский слой `SiteClient`.
>
> Главный тезис: **анимация — это не украшение, а инструмент восприятия.** Она
> либо объясняет переход состояния, либо даёт мгновенный отклик, либо предотвращает
> «дёрганое» появление. Если анимация не делает ничего из этого и пользователь
> видит её часто — её не должно быть. На сайте-витрине движение работает на доверие:
> сайт ощущается как настоящий дорогой бизнес, а не как шаблон.

---

## 0. TL;DR для генератора

При сборке сайта:

1. Используй **только** наши готовые классы и компоненты (раздел 4). Не пиши новые
   `@keyframes` и не вводи `transition: all`.
2. Анимируй **только** `transform` и `opacity` (плюс `filter: blur` точечно). Никогда —
   `width/height/margin/padding/top/left`.
3. Длительности UI-микровзаимодействий держи **под 300 мс**. Маркетинговое появление
   секций может быть длиннее (0.6–0.8 с) — это «explanatory», не UI.
4. Easing берёшь из темы: `--ease-out` для появления/ухода, `--ease-in-out` для
   движения на месте, `linear` для бесконечного движения (marquee/спиннер).
5. Reduced-motion и `(hover: hover)` уже зашиты в `globals.css` — не дублируй и не
   ломай их.
6. Интенсивность движения по сайту задаёт пресет `variation.animation`
   (`subtle` / `editorial` / `energetic`) — раздел 8.

## 1. Easing-кривые (уже в теме)

Кривые объявлены в `templates/app/globals.css` внутри `@theme inline` и доступны как
Tailwind-токены (`ease-[var(--ease-out)]`) и как CSS-переменные:

```css
/* easing-кривые (Emil Kowalski): сильнее встроенных CSS */
--ease-out:     cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out:  cubic-bezier(0.77, 0, 0.175, 1);
--ease-spring:  cubic-bezier(0.32, 0.72, 0, 1);
```

Встроенные `ease`/`ease-out` слишком слабые — у них нет «удара», который делает
движение намеренным. Поэтому используем кастомные кривые.

| Ситуация | Кривая | Почему |
| --- | --- | --- |
| Появление/уход элемента (reveal, preloader fade, dropdown, toast) | `--ease-out` | Стартует быстро → мгновенный отклик, пользователь сразу видит движение |
| Перемещение/морфинг **на экране** (сдвиг панели, репозиция) | `--ease-in-out` | Естественное ускорение и торможение |
| Drawer / drag / «живые», прерываемые жесты | `--ease-spring` | iOS-подобная кривая (из Ionic), ощущается как физика |
| Наведение, смена цвета | `ease` (встроенный ок) | Изменение мелкое, кастом не нужен |
| Бесконечное равномерное движение (marquee, спиннер, прогресс) | `linear` | Постоянная скорость без рывков |

**Запрещено: `ease-in` для UI.** Он стартует медленно — ровно в тот момент, когда
пользователь смотрит внимательнее всего, — и кажется тормозным. Dropdown с `ease-in`
на 300 мс *ощущается* медленнее, чем `ease-out` на тех же 300 мс.

## 2. Длительности

«Быстрее = производительнее» на уровне восприятия. Шкала Emil Kowalski:

| Элемент | Длительность |
| --- | --- |
| Отклик нажатия кнопки (`active:scale`) | 100–160 мс |
| Тултипы, мелкие поповеры | 125–200 мс |
| Dropdown, select | 150–250 мс |
| Модалки, drawer | 200–500 мс |
| Маркетинговое/объясняющее (reveal секций) | дольше — можно 600–800 мс |

**Правило: интерактивные UI-анимации — под 300 мс.** 180 мс ощущаются отзывчивее,
чем 400 мс.

Где это в нашем коде:
- Кнопка (`Button.tsx`): `duration-200` + `active:scale-[0.98]` — отклик ~200 мс,
  ближе к нижней границе. Это правильно для часто нажимаемого элемента.
- `ds-hover-lift`: `0.25s` на `transform` и `box-shadow` — наведение, не критично.
- Появление секций (`ds-reveal` 0.7 с, `ds-reveal-blur` 0.8 с) — это **explanatory**
  слой, не UI; видится один раз при скролле, поэтому дольше 300 мс допустимо.
- Preloader fade: `0.5s` — разовый разрыв состояний.

Не клади тяжёлые длительности на то, что повторяется десятки раз в день (hover по
карточкам, открытие меню) — это раздражает.

## 3. Что и как анимировать (производительность + честность движения)

### 3.1 Только `transform` и `opacity`
Эти свойства пропускают layout и paint и идут на GPU. Анимация `width/height/margin/
padding` дёргает все три стадии рендера и роняет кадры. Все наши keyframes построены
ровно на `transform`/`opacity` (+ `filter` в `ds-reveal-blur`):

```css
@keyframes ds-reveal      { from { opacity:0; transform: translateY(18px); }                  to { opacity:1; transform:none; } }
@keyframes ds-reveal-blur { from { opacity:0; transform: translateY(18px); filter: blur(6px);} to { opacity:1; transform:none; filter: blur(0);} }
@keyframes ds-scale-in    { from { opacity:0; transform: scale(0.96); }                         to { opacity:1; transform:none; } }
@keyframes ds-float       { 0%,100%{ transform: translateY(0);} 50%{ transform: translateY(-10px);} }
@keyframes ds-marquee     { from { transform: translateX(0);} to { transform: translateX(-50%);} }
```

### 3.2 CSS вместо JS под нагрузкой
CSS-анимации крутятся **вне main-thread**. Когда браузер занят (грузит страницу,
исполняет скрипты, рисует), JS-анимации на `requestAnimationFrame` роняют кадры, а
CSS остаётся плавным. Поэтому marquee, спиннер, reveal, float — это CSS; JS оставлен
лишь там, где нужен счёт значения или порог входа во вьюпорт (`Counter`,
`IntersectionObserver` в `SiteClient`).

### 3.3 Никогда не анимируй из `scale(0)`
Ничто в реальном мире не появляется из ничего. Стартуй с `scale(0.95–0.96)` + `opacity`.
У нас `ds-scale-in` начинается с `scale(0.96)` — корректно. Не вводи `scale(0)`.

### 3.4 `@starting-style` (по возможности)
Современный CSS-способ анимировать **появление** элемента без JS — `@starting-style`.
Он заменяет паттерн `useEffect → setMounted(true)`. Применяй для новых элементов,
появляющихся декларативно (например, инлайн-success формы), с graceful-фоллбэком на
`data-`атрибут там, где поддержка ещё неполная. Принцип тот же: стартовое состояние —
`opacity:0` + лёгкий `translateY`/`scale(0.95+)`, не `scale(0)`.

### 3.5 Blur как маска несовершенного перехода
Если кроссфейд двух состояний выглядит «грязно» при любом easing/длительности —
добавь короткий `filter: blur(2–6px)` на время перехода: глаз перестаёт видеть два
накладывающихся объекта. Именно так работает `ds-reveal-blur`. Держи blur **до 20px**
(тяжёлый blur дорог, особенно в Safari).

## 4. Наши инструменты

Две группы: **CSS-классы** (активирует `SiteClient`, добавляя `is-in` при попадании во
вьюпорт) и **React-компоненты** (`templates/components/ui/`).

### 4.1 CSS-классы (из `globals.css`)

| Класс | Что делает | Где применять |
| --- | --- | --- |
| `ds-reveal` | Появление снизу (`translateY(18px)`→0 + opacity), 0.7 с `--ease-out` | Заголовки секций, крупные блоки, hero-текст |
| `ds-reveal-blur` | То же + `blur(6px)`→0, 0.8 с | Hero-визуал, акцентные карточки — более «премиальный» вход |
| `ds-scale` | `scale(0.96)`→1 + opacity, 0.6 с | Изображения, медиа-карточки, отзыв-цитата |
| `ds-stagger` | Каскад дочерних элементов с задержкой `0/60/120…420 мс` (до 8 детей) | Сетки: услуги, фичи, портфолио, команда, отзывы |
| `ds-hover-lift` | `translateY(-4px)` + тень на hover, только `(hover:hover)` | Карточки услуг/портфолио/команды |
| `ds-float` | Бесконечное мягкое «парение» ±10px, 6 с `ease-in-out` | 1–2 декоративных элемента в hero (бейдж, фото) — не больше |
| `ds-skeleton` | Шиммер-плейсхолдер (1.4 с) | Заглушки контента до загрузки картинок |
| `ds-spinner` / `ds-marquee` | Спиннер / бегущая лента (`linear infinite`) | Preloader / trustbar-логотипы |

**Как активируется `is-in`:** `SiteClient` (монтируется один раз в `layout`) ставит
`IntersectionObserver` на селектор `.ds-reveal, .ds-reveal-blur, .ds-stagger, .ds-scale`
с `threshold: 0.12`, `rootMargin: "0px 0px -8% 0px"`, и при пересечении добавляет
`is-in` и `unobserve`. Есть отложенный повторный `scan()` через 350 мс — на случай
позднего монтирования контента. Это позволяет секциям **оставаться серверными
компонентами без хуков**: разметка на сервере, оживление — одним общим клиентским слоем.

### 4.2 React-компоненты

| Компонент | Назначение | Заметки по анимации |
| --- | --- | --- |
| `Preloader` | Брендовый экран загрузки | Скрывается после `window.load` (или через 350 мс если уже `complete`), фоллбэк 2600 мс; fade `opacity/visibility 0.5s --ease-out` через `[data-hidden]`. Вариант (`spinner`/`bar`/`dots`) берётся из `variation.preloader` → дополнительная непохожесть сайтов |
| `Counter` | Анимированный счётчик до `value` | Запускается при `threshold:0.4`; `easeOutCubic`, ~1400 мс; `Intl.NumberFormat("ru-RU")`; уважает reduced-motion (сразу финал) |
| `Marquee` | Бесконечная лента | Дублирует контент для бесшовного цикла, `linear infinite`, **пауза по hover** (`.ds-marquee-track:hover`), edge-fade через `mask-image` |
| `Reveal` | Программное появление-обёртка | Альтернатива классу `ds-reveal` с управляемым `delay`; сам проверяет reduced-motion. Использовать точечно — по умолчанию предпочитай CSS-класс `ds-reveal` (off-main-thread, без лишнего клиентского кода) |
| `Button` | Кнопка/CTA | `active:scale-[0.98]`, `transition-[transform,…] duration-200 ease-[var(--ease-out)]` — мгновенный отклик нажатия |

### 4.3 Рецепты применения по секциям

- **hero**: заголовок — `ds-reveal`; подзаголовок/буллеты — следом или внутри
  `ds-stagger`; визуал — `ds-reveal-blur` или `ds-scale`; максимум один `ds-float`
  на декоративном элементе. Оставляй негативное пространство, не перегружай движением
  первый экран.
- **trustbar / логотипы**: `Marquee` (вариант секции `marquee`) или статический ряд.
  Лента медленная и равномерная (`linear`), на hover замирает.
- **services / features / portfolio / team / reviews**: контейнер-сетку оборачивай в
  `ds-stagger` (каскад карточек **60 мс** между ними), каждую карточку — `ds-hover-lift`.
  **Не превышай 8 карточек на один `ds-stagger`** (дальше задержки не определены и
  ничего не появится с анимацией — лишь без неё). Для длинных списков дроби на группы.
- **stats / about-цифры**: числа через `Counter` (опыт, проекты, клиенты, %).
- **about / process**: заголовок `ds-reveal`, шаги/абзацы — `ds-stagger`.
- **любые медиа-заглушки** до подгрузки `<img>`: `ds-skeleton`.

**Stagger-дисциплина:** держи шаг каскада **30–80 мс** (у нас 60). Длинные задержки
делают интерфейс медленным. Stagger декоративен — он **никогда** не блокирует
взаимодействие.

## 5. `prefers-reduced-motion` (уже учтено)

Reduced motion — это **меньше и мягче**, а не «ноль». Оставляем `opacity`/цвет
(помогают понять, что появилось), убираем перемещение. В `globals.css`:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
  .ds-reveal, .ds-reveal-blur, .ds-stagger > * { opacity: 1 !important; }  /* контент сразу виден */
  .ds-float, .ds-marquee { animation: none !important; }                   /* убираем бесконечное движение */
}
```

Компоненты `Reveal` и `Counter` дополнительно сами проверяют
`matchMedia("(prefers-reduced-motion: reduce)")` и показывают финальное состояние
мгновенно. **Не вводи** новые бесконечные/перемещающие анимации без аналогичного
отключения здесь.

## 6. Hover только на «настоящем» ховере

Тач-устройства триггерят `:hover` по тапу → ложные срабатывания и «залипший» hover.
Поэтому все hover-движения спрятаны за медиа-запросом — это уже сделано для
`ds-hover-lift`:

```css
@media (hover: hover) and (pointer: fine) {
  .ds-hover-lift { transition: transform 0.25s var(--ease-out), box-shadow 0.25s var(--ease-out); }
  .ds-hover-lift:hover { transform: translateY(-4px); box-shadow: var(--shadow-card); }
}
```

Любой новый hover-эффект (увеличение, подсветка) **обязан** жить внутри
`@media (hover: hover) and (pointer: fine)`. Отклик нажатия (`:active`) в этот гейт не
оборачивается — тач должен чувствовать нажатие.

## 7. View Transitions API (опционально)

Для интерактивных **переключений состояний на одной странице** (слайдер «до/после»,
табы услуг/тарифов, фильтр портфолио) можно использовать React `<ViewTransition>` из
`next` — он работает в App Router. Это даёт нативно-плавный кроссфейд/морфинг между
двумя состояниями без библиотеки анимаций.

Применять **только** там, где есть реальное переключение состояния, и с **graceful
degradation**: где API не поддержан, переход просто происходит мгновенно — функция не
ломается. На сайте-витрине это редкий, «occasional» класс взаимодействия, поэтому
анимация уместна.

Короткий рецепт (табы/слайдер на клиентском островке):

```tsx
"use client";
import { unstable_ViewTransition as ViewTransition } from "next";
import { useState } from "react";

export function BeforeAfter({ before, after }: { before: string; after: string }) {
  const [showAfter, setShowAfter] = useState(false);
  return (
    <button onClick={() => setShowAfter((v) => !v)} className="block w-full">
      <ViewTransition>
        {/* key меняется → браузер анимирует переход между двумя кадрами */}
        <img key={String(showAfter)} src={showAfter ? after : before} alt="" />
      </ViewTransition>
    </button>
  );
}
```

Дисциплина: держи длительность перехода в UI-диапазоне (**150–250 мс**), используй
`--ease-out`, анимируй только `transform`/`opacity`. Не навешивай View Transitions на
весь скролл/появление секций — для этого есть CSS-классы `ds-*` (они off-main-thread и
не требуют клиентского кода в каждой секции). View Transitions — это «острова»
интерактивности, а не базовый слой страницы.

## 8. Как анимации поддерживают вариативность (анти-фингерпринт)

`variation_engine.py` детерминированно по домену/seed выбирает пресет анимаций:

```python
ANIM = ["subtle", "editorial", "energetic"]
PRELOADER = ["spinner", "bar", "dots"]
...
anim = r.pick(ANIM)
```

Он попадает в собранный `site.json` в двух местах:
- `variation.animation` — `"subtle" | "editorial" | "energetic"` (читается при сборке секций);
- `variation.preloader` — `"spinner" | "bar" | "dots"` (читает компонент `Preloader`);
- плюс запекается в `design.style` (например `"luxury-law-editorial"`).

Пресет `animation` управляет **интенсивностью и длительностью** движения по всему сайту
— два сайта с разными пресетами ощущаются по-разному и дают разный набор анимационных
сигнатур (ещё одна ось непохожести поверх палитры, шрифтов, радиуса, ритма и вариантов
секций). Маппинг при сборке:

| Пресет | Характер | Что использовать | Длительности / интенсивность |
| --- | --- | --- | --- |
| `subtle` | Сдержанный, дорогой минимум движения | Преимущественно `ds-reveal` (без blur), без `ds-float`, stagger короче (≈30–40 мс), marquee медленный | Reveal ≈0.5 с; hover-lift мягкий (−2…−3px); амплитуды минимальны |
| `editorial` | Сбалансированный дефолт, «редакционный» | `ds-reveal` + `ds-reveal-blur` на hero/медиа, `ds-stagger` 60 мс, аккуратный `ds-hover-lift`, 0–1 `ds-float` | Reveal 0.6–0.8 с (значения по умолчанию в `globals.css`) |
| `energetic` | Живее, заметнее, чуть быстрее UI | `ds-reveal-blur`/`ds-scale` шире, `ds-stagger` 60–80 мс, `ds-float`, более выраженный hover-lift (−4px) | Reveal чуть короче и «упругее»; marquee быстрее |

Практически: пресет влияет на **выбор классов** для секций и на параметры компонентов
(`Marquee duration`, `Counter duration`, шаг каскада, наличие `ds-float`). Базовые
keyframes/easing не меняются — меняется их применение и тайминги. Reduced-motion и
hover-гейт остаются неизменными при любом пресете.

## 9. Чек-лист ревью анимаций (перед сдачей сайта)

| Проверка | Должно быть |
| --- | --- |
| `transition: all` где-либо | Нет — только перечисленные свойства |
| Анимация не на `transform`/`opacity`/`blur` | Нет (никаких `width/height/top/margin`) |
| `scale(0)` на входе | Нет — старт от `scale(0.95+)` + opacity |
| `ease-in` на UI | Нет — `--ease-out` или кастомная кривая |
| UI-микровзаимодействие > 300 мс | Нет (reveal секций — исключение, это explanatory) |
| Hover-движение вне `(hover:hover)` | Нет — всё в медиа-гейте |
| Кнопки без `active:scale` | Нет — отклик нажатия обязателен |
| `ds-stagger` с > 8 детьми | Нет — разбить на группы |
| Бесконечное движение без отключения в reduced-motion | Нет — добавить в `@media (prefers-reduced-motion)` |
| Preloader не скрывается | Проверить fade и фоллбэк 2600 мс |
| Любое слово демо/тест/placeholder в анимациях/лоадере | Нет (правило сайта-витрины) |

Совет Emil Kowalski напоследок: **смотри анимации на свежую голову на следующий день**
и в замедленном режиме (DevTools → Animations, 2–5× медленнее). На замедлении видны
рассинхрон свойств, неверный `transform-origin` и резкий easing, которые на полной
скорости незаметны. Невидимые детали в сумме становятся видимыми — именно они отличают
«дорогой» сайт от шаблона.
