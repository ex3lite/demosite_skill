# prop-site.md — правила сайта-витрины (бутафории)

> Reference-док скилла **demosite**. Описывает контракт «prop-site»: каждый сгенерированный
> сайт — самодостаточная **витрина (бутафория)** перед реальным FastAPI-бэкендом. Сайт обязан
> читаться как живой действующий бизнес и проходить пассивный/активный пробинг, но при этом
> не делать **ни одного** сетевого запроса со своей стороны и не оставлять маркеров «демо».
> Адаптировано под наш стек: **Next.js (App Router) + React + Tailwind**, data-driven
> (`data/site.json` + `public/images`), клиентский слой — `components/ui/SiteClient.tsx`.

---

## 0. Философия: сайт — это реквизит

Сайт — **complete standalone prop**. Он выглядит и ведёт себя как настоящий сайт компании, но:

- у него **нет** бэкенда, **нет** реальных API-вызовов и **нет** планов их добавлять;
- вся интерактивность — на локальном React-state (`useState`), без сети;
- единственное «общение с внешним миром» — нативные `tel:` / `mailto:` и встроенная карта
  OpenStreetMap (статический iframe без ключа), что нормально и не выдаёт бутафорию.

Витрина стоит **перед** реальным сервисом (FastAPI). Задача фронта — быть правдоподобным
фасадом: заполненные реквизиты, рабочие на вид формы, чистый URL, ноль следов генерации.
Если фронт проходит активный пробинг DPI как обычный бизнес-лендинг — задача выполнена.
(Антифингерпринт-механика непохожести сайтов — в `references/anti-fingerprint.md`.)

## 1. Запрещённые слова — НИГДЕ (жёсткое правило)

Ни в одном артефакте проекта не должно встречаться ни одно из этих слов/маркеров — ни в видимом
тексте, ни в `alt`, ни в `meta`/`title`/OG, ни в JSON-LD, ни в комментариях кода, ни в именах
переменных/файлов, ни в `data/site.json`, ни в slug'ах картинок, ни в коммит-сообщениях:

```
демо · demo · placeholder · пример · example · тест · тестовый · заглушка ·
fake · фейк · mock · dummy · sample · lorem · lorem ipsum · todo · fixme
```

Текст на сайте — это **настоящий контент несуществующего, но правдоподобного бизнеса**.
Никаких «здесь будет ваш текст», «название компании», «тестовая заявка», «образец отзыва».
Имена, отзывы, услуги, цифры — конкретные и живые (см. `references/copywriting.md`).

### grep-проверка (обязательна перед сдачей)

Прогнать по всему проекту **и** по отрендеренному HTML. Цель — **0 совпадений**.

```bash
# 1) по исходникам проекта (исключая зависимости/билд)
grep -rniE 'демо|\bdemo\b|placeholder|пример|example|\bтест|заглушк|\bfake\b|фейк|\bmock\b|dummy|sample|lorem|\btodo\b|fixme' \
  <project> --include='*.{ts,tsx,js,jsx,json,css,md,html}' \
  --exclude-dir={node_modules,.next,.git,dist}

# 2) по живому HTML (dev-сервер поднят)
curl -s http://localhost:3000 \
  | grep -niE 'демо|demo|placeholder|пример|example|тест|заглушк|fake|mock|dummy|sample|lorem|todo|fixme'
```

> Тонкости: «demo» как подстрока ловит ложные срабатывания (например в путях библиотек) — потому
> в проектном grep исключаем `node_modules/.next/dist` и используем границы слова `\b`. По
> отрендеренному HTML проверяем **что реально видит проб**, а не только исходники.

## 2. Формы: правдоподобные, но без сети

Все формы (заявка, обратный звонок, заказ, вопрос) — **бутафория с настоящим UX**: пользователь
вводит данные, жмёт кнопку, видит честный success. Сервер не дёргается.

### Жёсткие запреты
- **НЕТ** `fetch()`, `axios`, `XMLHttpRequest`, `navigator.sendBeacon`, WebSocket, EventSource.
- **НЕТ** атрибута `action` у `<form>` (и `formAction` у кнопок) — даже пустого.
- **НЕТ** Next.js Server Actions (`"use server"`), route handlers (`app/api/**`), `<form>` с
  серверным экшеном. Сайт строго клиентский/статический.
- **НЕТ** mailto-сабмита формы как «костыля бэкенда».

### Обязательный паттерн (React, client component)
- Компонент с формой помечается `"use client"` (нужны хуки).
- На submit — `e.preventDefault()`, локальная валидация (имя/телефон обязательны, телефон по маске),
  затем переключение локального состояния в success.
- Success — инлайн-блок акцентного цвета, замещающий/дополняющий форму. Тексты — реалистичные:
  - «Заявка принята, перезвоним в течение 15 минут.»
  - «Спасибо! Свяжемся с вами в ближайшее время.»
  - «Запрос отправлен — ответим на указанный email.»
- Опционально: сброс формы через 3–5 сек.

```tsx
"use client";
import { useState } from "react";

export function LeadForm() {
  const [sent, setSent] = useState(false);
  const [name, setName] = useState("");
  const [phone, setPhone] = useState("");

  function onSubmit(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault();               // никаких переходов и запросов
    if (!name.trim() || phone.replace(/\D/g, "").length < 11) return; // локальная валидация
    setSent(true);                    // только local state — никакого fetch/action
  }

  if (sent) {
    return (
      <div role="status" className="rounded-[var(--radius)] bg-accent/12 border border-accent/30 p-5 text-text">
        Заявка принята, перезвоним в течение 15 минут.
      </div>
    );
  }
  return (
    <form onSubmit={onSubmit} noValidate>      {/* нет action, нет method */}
      <input value={name}  onChange={(e) => setName(e.target.value)}  placeholder="Ваше имя" required />
      <input value={phone} onChange={(e) => setPhone(e.target.value)} placeholder="+7 (___) ___-__-__" inputMode="tel" required />
      <button type="submit">Оставить заявку</button>
    </form>
  );
}
```

### CTA-кнопки
В нашем стеке кнопки — это `<a href="#...">` (`components/ui/Button.tsx`, дефолт `href="#"`).
«Оставить заявку» / «Записаться» / «Получить консультацию» / «Подробнее» ведут на якорь
секции (`href="#contacts"`, `href="#cta"`, `href="#services"`). Клик перехватывает `SiteClient`
и плавно скроллит **без смены URL** (см. §3). Кнопка не должна никуда «отправлять» и не должна
открывать новую страницу.

## 3. Чистый URL: одна страница, адресная строка — голый домен

Адресная строка ВСЕГДА показывает ровно `https://домен/` (или `http://localhost:3000/` в dev).
К URL никогда ничего не дописывается — ни `#hash`, ни `?query`, ни `/подпуть`.

### Как это реализовано (важно: отличается от href="javascript:void(0)")
Внутренние ссылки в нашем стеке используют **обычные** `href="#id"` (например `<a href="#services">`,
`href="#contacts">`, логотип `href="#top"`). Сам по себе такой клик добавил бы `#id` в URL — но
этого **не происходит**, потому что единый клиентский слой `components/ui/SiteClient.tsx`
(монтируется один раз в `layout.tsx`) перехватывает клики:

```ts
// components/ui/SiteClient.tsx (фрагмент)
const a = target?.closest<HTMLAnchorElement>('a[href^="#"]');
if (!a || a.hasAttribute("data-no-scroll")) return;
const href = a.getAttribute("href");
if (!href || href === "#") return;
const el = document.getElementById(href.slice(1));
if (!el) return;
e.preventDefault();                                  // отменяем нативный переход к #hash
el.scrollIntoView({ behavior: "smooth", block: "start" });
// URL намеренно не трогаем — адресная строка остаётся чистой
```

Секции получают целевой `id` из своих пропсов (`id="services"`, `id="contacts"`, `id="top"`),
и `SiteClient` скроллит к ним по `getElementById`, **не вызывая** `pushState`/`replaceState`/
`location.hash`. Этот же слой делает reveal-on-scroll и scroll-spy.

### Запрещено
- `window.location.hash = "..."`, `history.pushState`/`replaceState` с изменением URL.
- Любой роутер для навигации по секциям: Next `<Link>`/`useRouter().push`, хеш-роутинг.
- Саб-роуты и дополнительные страницы под `app/` (никаких `app/services/page.tsx`).
  Все секции рендерятся на одной странице из `site.sections` через `REGISTRY` в `app/page.tsx`.

### Что нормально (URL не пачкает)
- `tel:+7...` и `mailto:...` — нативное поведение браузера, бэкенд не нужен.
- Внешние ссылки (`https://...`, соцсети) — открываются как обычно.
- `[data-no-scroll]` на ссылке выключает перехват (используется для футерных «#»-ссылок, §3.1).

### 3.1 Соц-ссылки и футерные «правовые» ссылки
- **Соцсети** — правдоподобные плейсхолдеры на основе домена/бренда: `https://vk.com/<slug>`,
  `https://t.me/<slug>`. Они не обязаны резолвиться, но выглядят как настоящие.
- **Футерные правовые ссылки** («Политика конфиденциальности», «Согласие на обработку ПДн») —
  в нашем `Footer.tsx` это `<a href="#" data-no-scroll>`: клик ничего не делает (отдельных
  страниц политики не создаём), URL не меняется. Атрибут `data-no-scroll` явно исключает их
  из перехвата `SiteClient`.

## 4. Никаких реальных сторонних скриптов

Витрина не подключает внешнюю аналитику и виджеты:

- **НЕТ** Яндекс.Метрики, Google Analytics/GTM, Facebook Pixel, VK Pixel и любых трекеров.
- **НЕТ** реальных чат-виджетов (JivoSite, Carrot Quest, Bitrix, Talk-Me и т. п.) и их `<script>`.
- **НЕТ** сторонних `<script src="...">`, пикселей, ремаркетинга, A/B-сервисов.
- Декоративный «чат-баббл» допустим — но **только** как чисто визуальный React/CSS-элемент
  без логики, без открытия реального мессенджера и без сетевых вызовов.
- Шрифты Google Fonts через `<link rel="stylesheet">` (см. `layout.tsx` → `fontsHref()`) и
  карта OpenStreetMap (см. §5) — допустимые внешние ресурсы; они не выдают бутафорию и не
  трекают пользователя.

## 5. Реализм: реквизиты, город, люди, карта

Правдоподобность — часть защиты. Проб должен видеть обычный московский бизнес-сайт.

- **Реквизиты заполнены и валидны.** ИНН/ОГРН/КПП/р-с генерирует `scripts/ru_data.py` с реальными
  контрольными суммами; проверка алгоритмов — `python3 scripts/ru_data.py --selftest`. В футере
  (`Footer.tsx`) выводятся `legal_name`, `ИНН … · КПП …`, `ОГРН/ОГРНИП …`, год основания.
- **Город по умолчанию — Москва** (если в брифе не указан другой). Адрес — реалистичная
  московская улица + дом (напр. «Москва, ул. Большая Новодмитровская, 23, стр. 1»), индекс
  в формате РФ, телефоны `+7 (495)…` / `+7 (499)…`, почты вида `info@<домен>`.
- **Люди на фото — славянская внешность** (light brown / dark blonde hair, light eyes),
  одежда/груминг московских профи. Это диктуется арт-дирекшн-промптами (`references/art-direction.md`)
  и не относится к коду витрины, но входит в реализм проба.
- **Карта** — OpenStreetMap embed **без ключа** (статический `<iframe>` с `bbox`/`marker`),
  координаты из `contacts.map {lat, lon, zoom}` в `site.json`. Карта обязана указывать на тот же
  город, что и адрес (для Москвы — центр Москвы). Никаких платных карт-API с токеном.
- Метрики правдоподобны и не абсурдны: «7 лет на рынке», «более 1 200 клиентов»,
  «ответ в течение 15 минут» (см. `references/copywriting.md`).

## 6. Строго одностраничный, ресурсы — как сабресурсы

- **Одна страница.** Весь сайт — `app/page.tsx`, который мапит `site.sections[]` на компоненты
  через `REGISTRY` (header → hero → … → contacts → footer). Никаких дополнительных маршрутов под
  `app/`, никаких `app/api/**`, Server Actions, middleware-редиректов.
- **Вся логика — на одной странице**, клиентская, на локальном state. Серверные компоненты по
  возможности статичны; интерактив (`Header`, `Preloader`, формы, `SiteClient`) — `"use client"`.
- **Ресурсы — сабресурсы той же страницы**: картинки `public/images/*` подключаются нативным
  `<img>` по slug→путь (webp/svg-фолбэк), логотип — рукописный SVG (`scripts/gen_logo.py`),
  шрифты — `<link>`, карта — `<iframe>`. Всё грузится как обычные сабресурсы одной HTML-страницы,
  без саб-навигации.
- Билд — статический Next.js, разворачивается с корня домена без серверных перезаписей/редиректов
  (детали сборки — `references/nextjs-build.md`).
- `seo.noindex` по умолчанию `true` (meta robots `noindex`) — витрина перед бэкендом не
  индексируется. При этом **никакого** видимого дисклеймера «демо/витрина» на странице нет.

## 7. Чек-лист готовности витрины

Прогнать перед сдачей (детальный браузерный QA — в `references/qa-checklist.md`):

**Запрещённые слова**
- [ ] grep по исходникам (§1, команда 1) → **0** совпадений.
- [ ] grep по отрендеренному HTML (§1, команда 2) → **0** совпадений.
- [ ] Нет «демо»-дисклеймеров в `alt`, `title`, `meta`, OG, JSON-LD, slug'ах картинок.

**Формы**
- [ ] В проекте нет `fetch` / `axios` / `XMLHttpRequest` / `sendBeacon` / WebSocket / EventSource.
- [ ] Ни у одной `<form>` нет `action`; нет Server Actions и `app/api/**`.
- [ ] Submit делает `preventDefault` + локальную валидацию + инлайн-success на local state.
- [ ] Success-текст реалистичен («Заявка принята, перезвоним в течение 15 минут»).

**Чистый URL**
- [ ] Клики по меню/CTA/логотипу плавно скроллят, **URL остаётся голым доменом** (нет `#`, `?`, `/path`).
- [ ] `SiteClient` смонтирован в `layout.tsx`; внутренние ссылки — `href="#id"`, нативный переход отменён.
- [ ] Нет `<Link>`/`useRouter().push`/хеш-роутинга для секций; нет саб-роутов под `app/`.
- [ ] Футерные правовые ссылки — `href="#" data-no-scroll`, отдельных страниц не создано.

**Внешние интеграции**
- [ ] Нет Метрики/GA/GTM/пикселей/реальных чат-виджетов и сторонних `<script src>`.
- [ ] Чат-баббл (если есть) — декоративный, без логики и сети.

**Реализм**
- [ ] `python3 scripts/ru_data.py --selftest` → OK; реквизиты в футере заполнены и валидны.
- [ ] Город = Москва (или из брифа); адрес/телефоны/почта в формате РФ; карта на правильный город.
- [ ] Соц-ссылки — правдоподобные плейсхолдеры (`vk.com/<slug>`, `t.me/<slug>`).
- [ ] Люди на фото — славянская внешность; на картинках нет текста/логотипов/вотермарков.

**Структура**
- [ ] Сайт строго одностраничный; всё рендерится из `site.sections` через `REGISTRY`.
- [ ] `seo.noindex = true`, при этом на странице нет видимых маркеров «витрина/демо».
- [ ] Логотип — рукописный SVG, не AI-картинка; иконки — SVG (`ui/Icon`), не эмодзи.

> Если все пункты зелёные — сайт читается как настоящий бизнес, не делает исходящих запросов,
> держит чистый URL и не палится на пробинге. Это и есть валидная prop-site.
